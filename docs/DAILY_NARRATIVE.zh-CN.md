# Windows 本地日摘要

[English](DAILY_NARRATIVE.md) | [简体中文](DAILY_NARRATIVE.zh-CN.md)

Windows SELENE 会读取已经生成的按日合并文件，在本机创建一份更便于阅读的中文日摘要。它只使用确定性规则，不访问网络、不调用云端翻译或模型，也不会写回或改变合并 JSON。

## 位置与使用方式

在 Windows SELENE 的同步区域点击“生成本地可读摘要”，或等待 10 秒一次的同步维护周期。源文件和产物分别位于：

```text
<数据根>/Archive/Merged/SELENE-merged-v1-YYYY-MM-DD.json
<数据根>/Archive/Narrative/SELENE-narrative-v1-YYYY-MM-DD.zh-CN.json
<数据根>/Archive/Narrative/SELENE-narrative-v1-YYYY-MM-DD.zh-CN.md
```

摘要会在新的 Android 或 Windows 快照归档后自动重建，因此延迟同步到达的数据会反映在同一天的下一份摘要中。

## 规则与内容

摘要 JSON 记录输入合并文件名和 SHA-256，并包含：

- 去重后的事件与来源快照数量；
- 前台活跃累计时长、主要应用和至少 1 分钟的活动时段；
- 应用的来源平台；同名应用会明确显示为“手机”或“电脑”，例如 `QQ（手机）`、`QQ（电脑）`；
- 常见应用包名到中文名称的本地映射；
- 位置样本与本地地点标签数量；
- 已确认的持续移动段、持续时间、距离和按距离/时间计算的平均速度；
- 最后一条设备状态中的电量（存在时）。

活动时段会按应用消除采样抖动：同一应用相邻记录间隔不超过 2 分钟时视为同一连续段；
因此短暂的跨设备采样交错不会把一段使用拆成许多碎片。

当前合并文件兼容旧版本：优先读取事件的 `platform`，缺失时根据稳定事件 ID 的
`SELENE-auto-*`（Android）和 `SELENE-windows-*`（Windows）前缀识别来源。无法识别的
历史或第三方事件显示为“设备”，不会被错误归入手机或电脑。

单段最高速度超过 `8 m/s` 时，摘要会把它标记为疑似定位跳点。该峰值不会被描述成真实步速；平均速度仍依据该段的距离和持续时间计算。摘要不输出原始坐标、窗口标题、可执行文件路径、浏览器 URL 或其他原始敏感字段。

## 数据边界

`Archive/Merged` 和 `Archive/Narrative` 都是派生数据。事实来源仍是 Android 和 Windows 的不可变 `SELENE-v1-*` 快照。删除某个摘要文件只会让 Windows SELENE 在下次维护或手动生成时重建它；不要把摘要当作 HYPERION 的导入源，也不要据此删除原始快照。

生成器在同一 Windows 进程内串行运行，并先完整写入临时文件、关闭文件句柄，再原子替换目标，避免手动生成与自动维护互相写坏输出。目标短暂被其他程序占用时会有限重试；失败会保留上一份健康摘要并在 SELENE 界面和日志中报告。
